# Maritime Ferry & Weather Dashboard

## P — Problem & constraints

Combine ferry schedules and maritime-condition data in a usable no-code interface despite external provider data formats, search/filter requirements and presentation constraints.

## A — Architecture & decisions

External REST/JSON sources feed Bubble.io data and workflows. Incoming ferry information is normalized for filtering/search, while custom HTML/CSS presentation blocks handle time-segmented weather and sea-state information where standard no-code components are insufficient.

## C — Contribution & delivery

OSYSTIC configured the external-data integrations, ferry-schedule presentation, maritime weather/sea-state metrics, filtering-oriented data structures, custom responsive visual blocks and separate coastal/ferry application surfaces.

## Engineering highlights

- Mapped external REST/JSON provider structures into Bubble data/workflow patterns.
- Normalized ferry data before user-facing filtering and presentation.
- Combined no-code workflows with custom HTML/CSS for presentation needs beyond built-in components.
- Structured weather and sea-state information into time-segmented visual blocks.
- Preserved original project documentation and demo evidence privately because the application lives in a no-code workspace.
